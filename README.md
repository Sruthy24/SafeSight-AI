## Authentication

SafeSight AI uses **JWT (JSON Web Token)** authentication via `flask-jwt-extended`.

| Endpoint | Method | Auth required | Description |
|---|---|---|---|
| `/api/auth/register` | POST | ❌ | Create new account |
| `/api/auth/login` | POST | ❌ | Login, receive JWT |
| `/api/auth/me` | GET | ✅ | Get current user profile |
| `/api/auth/logout` | POST | ✅ | Server-side logout confirmation |
| `/api/health` | GET | ❌ | System health (public) |
| All other `/api/*` | * | ✅ | Protected — require Bearer token |

- Passwords are hashed with **Werkzeug** (`pbkdf2:sha256`). Plain-text passwords are never stored.
- Tokens are valid for **24 hours** and stored in `localStorage`.
- A 401 response anywhere in the app clears the token and redirects to `/login`.

### Environment Variables (`backend/.env`)
```
JWT_SECRET_KEY=<auto-generated 64-char hex>
FLASK_ENV=development
```

## 2. Project Overview


SafeSight AI is designed to improve workplace safety compliance across construction, manufacturing, and industrial facilities. Using deep learning object detection (Ultralytics YOLOv8) and computer vision (OpenCV), the system analyzes visual media (images, recorded CCTV videos, and live webcam feeds) to detect human workers and evaluate whether they comply with mandatory Personal Protective Equipment rules:
- **Certified Hard Hats / Helmets** (Prevents head injuries from falling objects)
- **High-Visibility Safety Vests** (Ensures vehicular and heavy machinery visibility)
- **Protective Eyewear / Goggles** (Protects against debris, chemicals, and welding sparks)

When non-compliant workers are detected, SafeSight AI flags violations, assigns severity ratings (**High**, **Medium**, **Low**), records visual snapshots of the violation, enables safety officers to conduct interactive audits (**Detected**, **Verified**, **False Positive**, **Requires Review**), and generates downloadable, OSHA-style PDF compliance reports.

## 2. Key Features & Milestones

- **Milestone 1: Image & Video Upload Hub**
  - Drag-and-drop file upload supporting JPG, JPEG, PNG, WEBP (Images) and MP4, AVI, MOV (Videos).
  - Client-side and server-side file type and 50 MB size limit validation.
  - Pre-upload media preview and configurable inspection parameters (confidence threshold slider: default 0.40; individual PPE toggles).
- **Milestone 2: YOLOv8 PPE Detection & Spatial Association**
  - Deep learning inference via Ultralytics YOLOv8.
  - Anatomical sub-region spatial association: checks if helmets overlap the worker's head region, vests overlap the torso, and goggles overlap the eye region.
  - Non-blocking asynchronous background worker for video processing with chronological violation timelines and frame timestamps (`MM:SS`).
  - Interactive Live Monitor with simulated 3-channel industrial CCTV dashboard and browser webcam demonstration.
- **Milestone 3: Audit Workflow & PDF Report Generation**
  - Side-by-side inspection viewer (Original vs Annotated Detection image).
  - "Violations Identified" table with cropped snapshots, confidence scores, and instant audit status updating (`PATCH /api/violations/<id>`).
  - Searchable and filterable Events & Audit Log table.
  - Automated PDF Safety Compliance Report generation using ReportLab with executive scorecard, violation breakdown, embedded snapshots, and safety officer recommendations.

## 3. Technology Stack

### Frontend
- **Framework**: React.js (Vite)
- **Routing**: React Router DOM v7
- **Data Visualization**: Recharts (Bar Charts, Donut Charts)
- **Icons**: Lucide React
- **Styling**: Custom responsive CSS with dark navy industrial sidebar, crisp light dashboard canvas, and light/dark theme toggle.

### Backend
- **Framework**: Python Flask REST API
- **CORS**: Flask-CORS
- **Deep Learning**: Ultralytics YOLOv8
- **Computer Vision**: OpenCV (`opencv-python`) & Pillow (`PIL`)
- **Report Generation**: ReportLab
- **Database**: SQLite3 (Thread-safe connection pool with foreign key constraints)

## 8. PPE Model Configuration & Demo Mode

### 1. Using a Custom Trained PPE Model (`best.pt`)
- If you have trained a custom YOLOv8 model for PPE detection (classes: `helmet`, `vest`, `goggles`, `person`), copy the `.pt` file to:
  ```
  backend/models/best.pt
  ```
- Restart the backend. The dashboard status indicator will show: `Custom PPE YOLOv8`.

### 2. Using Base Pretrained Model (`yolov8n.pt`) with Demonstration Mode
- When using `yolov8n.pt`, the model reliably detects **actual human workers** in any image or video.
- Because base COCO does not include safety hard hats or hi-vis vests, SafeSight AI features a **clearly marked Demonstration Mode**:
  - The UI highlights that demo rule evaluation is active.
  - Violations are classified with `audit_status = 'Requires Review'` or `audit_status = 'Detected'`.
  - Full transparency is preserved with zero false claims of raw detection capabilities.

## 9. REST API Documentation

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/health` | Returns backend health, AI engine status, and configuration. |
| `GET` | `/api/dashboard/stats` | Returns aggregated metrics, PPE category counts, and chart data. |
| `POST` | `/api/analyze/image` | Uploads and analyzes a workplace image; returns detections and violation table. |
| `POST` | `/api/analyze/video` | Initiates asynchronous video analysis job; returns `job_id`. |
| `GET` | `/api/jobs/<job_id>` | Polls video job progress, sampled frame count, and chronological timeline. |
| `GET` | `/api/inspections` | Returns paginated inspection history. |
| `GET` | `/api/inspections/<id>` | Returns single inspection details with all associated violations. |
| `GET` | `/api/violations` | Searchable violation list with severity and audit status filters. |
| `PATCH` | `/api/violations/<id>` | Updates audit status (`Verified`, `False Positive`, `Requires Review`). |
| `POST` | `/api/reports/generate` | Generates official PDF compliance audit report via ReportLab. |
| `GET` | `/api/reports` | Lists previously generated PDF reports stored in SQLite. |
| `GET` | `/api/reports/<id>/download` | Downloads the generated `.pdf` report file. |
| `GET` | `/api/files/<path>` | Securely serves uploaded and processed visual snapshots. |

## 10. Database Schema (SQLite)

- **`inspections`**: Stores overall inspection metadata (code, filename, media type, worker count, PPE count, violations count, compliance rate %, latency).
- **`violations`**: Individual safety violation incidents linked to inspections via foreign keys (violation type, severity, confidence, bounding boxes, snapshot image path, audit status, notes).
- **`video_jobs`**: Asynchronous video processing status, progress percentage, sampled frame counter, duration, and chronological violation timeline JSON.
- **`reports`**: Generated PDF audit reports catalog (code, title, filename, file path, inspection count, violation count, filter criteria).
